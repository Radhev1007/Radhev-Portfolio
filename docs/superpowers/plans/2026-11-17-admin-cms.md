# Admin CMS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A password-protected `/admin` where the owner edits all site text and images, stored in Postgres + Vercel Blob, live without redeploy.

**Architecture:** `lib/content.ts` stays as typed defaults. A new content store reads one validated JSON document from Neon Postgres (falls back to the defaults on empty/invalid/error) and is cached under a tag that saving revalidates. Server components call `getContent()`; client components read it from a context provider fed by the server layout. The admin is a separate route group with its own layout, so it carries none of the portfolio chrome.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, Tailwind v4, zod, `@neondatabase/serverless`, `@vercel/blob`, sharp, vitest (new, for unit tests).

**Spec:** `docs/superpowers/specs/2026-11-17-admin-cms-design.md`

## Global Constraints

- `AGENTS.md`: this is NOT the Next.js you know. Read the relevant guide in `node_modules/next/dist/docs/` before writing route handlers, caching/revalidation, cookies or layouts.
- Public pages stay statically cached; never hit the DB per visitor request.
- If the DB is unset, empty, unreachable or holds invalid data, the public site renders from `lib/content.ts` defaults and does not error.
- Secrets only in env vars (`DATABASE_URL`, `BLOB_READ_WRITE_TOKEN`, `ADMIN_PASSWORD`, `ADMIN_SESSION_SECRET`); never in the repo or client bundle.
- Admin: HttpOnly signed expiring cookie, every admin page and write endpoint checks it server-side, `noindex`, excluded from sitemap.
- Public URLs, visuals and metadata must be unchanged by the refactor.
- `npm run build:static` must still succeed (it ships defaults only, no admin, no API).
- Uploaded images: JPEG/PNG/WebP only, 8 MB input cap, converted to WebP, max width 1600, never upscaled.
- Do not commit; leave the working tree for the owner to review. (Commit steps below apply only if the owner asks for commits.)

## Review Focus

- Stored document from an older shape (missing/extra field): site must fall back or tolerate it, never crash. Test in Task 3.
- Project `slug` empty, duplicated, or with spaces/uppercase/slashes: rejected on save (would break `/work/[slug]`). Test in Task 1.
- Invalid colour value in a project `palette`: rejected with a field-level message. Test in Task 1.
- Corrupt, oversized or wrong-type upload: 4xx with a message, never a 500. Test in Task 5.
- Repeated wrong passwords: blocked after 5 tries/15 min; any write without a valid session returns 401. Test in Tasks 2 and 6.
- Save while the DB is down: admin shows a clear error, public site keeps working. Test in Task 3.

### Task 2: Admin auth

**Files:**
- Create: `lib/admin/auth.ts`, `lib/admin/auth.test.ts`, `app/api/admin/login/route.ts`, `app/api/admin/logout/route.ts`

**Interfaces:**
- Produces (in `lib/admin/auth.ts`):
  - `createSessionToken(secret: string, now?: number): string` — payload is expiry (7 days), HMAC-SHA256 signed.
  - `verifySessionToken(token: string | undefined, secret: string, now?: number): boolean`
  - `checkPassword(input: string, expected: string): boolean` — timing-safe.
  - `createRateLimiter(opts: { max: number; windowMs: number }): { hit(key: string, now?: number): boolean }` — returns `false` when blocked. Best-effort in-memory (documented limitation on serverless).
  - `isAdmin(): Promise<boolean>` — reads the session cookie via Next's cookies API and verifies it; `false` if env vars are missing.
  - Cookie name constant `ADMIN_COOKIE`.
- Routes: `POST /api/admin/login` `{ password }` → 200 + Set-Cookie (HttpOnly, Secure in prod, SameSite=Lax, Path=/) | 401 | 429 (5 failures per IP per 15 min) | 503 if admin env vars are not configured. `POST /api/admin/logout` clears the cookie.

- [ ] **Step 1: Write failing tests:** token round-trips; expired token rejected; tampered payload rejected; wrong secret rejected; `undefined` token rejected; `checkPassword` true/false and different-length inputs do not throw; limiter allows 5 hits then blocks the 6th, and allows again after the window.
- [ ] **Step 2: Run — expect FAIL. Implement. Run — expect PASS.**
- [ ] **Step 3: Implement the two route handlers per the contract above (read the Next route-handler and cookies docs first).**
- [ ] **Step 4: Manual check with `curl`:** wrong password → 401; sixth wrong attempt → 429; correct password sets the cookie; no env vars → 503.

### Task 3: Content store

**Files:**
- Create: `lib/content-store.ts`, `lib/content-store.test.ts`

**Interfaces:**
- Consumes: `parseContent`, `defaultContent`, `ContentData` (Task 1).
- Produces:
  - `type ContentDb = { read(): Promise<unknown | null>; write(doc: unknown): Promise<void> }`
  - `neonDb(): ContentDb | null` — `null` when `DATABASE_URL` is unset. Table `content (id int primary key, data jsonb not null, updated_at timestamptz not null default now())`, single row `id = 1`, created with `CREATE TABLE IF NOT EXISTS` on first use.
  - `loadContent(db: ContentDb | null): Promise<{ content: ContentData; source: "database" | "defaults" }>` — never throws.
  - `getContent(): Promise<ContentData>` — server-only, cached under tag `CONTENT_TAG = "content"`, uses `loadContent(neonDb())`. In `build:static` mode returns defaults without touching the DB.
  - `saveContent(content: unknown, db?: ContentDb | null): Promise<{ ok: true } | { ok: false; status: 400 | 503; message: string; issues?: ... }>` — validates with `parseContent`, writes, then revalidates `CONTENT_TAG`.

- [ ] **Step 1: Write failing tests with an in-memory fake `ContentDb`:** empty DB → defaults, source `defaults`; valid stored doc → returned, source `database`; stored doc with a missing required field → defaults; stored doc with an extra unknown field → still loads (unknown keys stripped); `read()` throws → defaults; `db === null` → defaults; `saveContent` with invalid input → `{ok:false,status:400}` and nothing written; `saveContent` when `write()` throws → `{ok:false,status:503}`; a valid save then `loadContent` returns the saved value.
- [ ] **Step 2: Run — expect FAIL. Implement. Run — expect PASS.** Keep revalidation out of the unit-tested core (inject or isolate it) so tests do not need a Next runtime.
- [ ] **Step 3: Read the Next docs for the current caching and `revalidateTag` API (signature may differ from older versions) and wire `getContent` accordingly.**
